# SWS Freelance — Website

A data-driven Astro + Tailwind CSS site for a freelance services business
(Amazon e-commerce services + data entry / virtual assistant services).
"SWS Freelance" is a **temporary placeholder brand name**, deliberately kept
separate from SWS Global LLC — change it in one place, see below.

Everything in this project is free to build, run, and test. No domain,
hosting plan, theme, plugin, or subscription is required until you choose to
buy a domain at the very end.

## Core architectural rule

**Categories, services, portfolio items, and FAQs are data, not code.** They
live as Markdown files under `src/content/`, validated by schemas in
`src/content.config.ts`. Pages, the header's Services dropdown, the
footer, the sitemap, and related-services/related-FAQ sections all
generate themselves from that data. This is what makes "add a new Fiverr
gig without rebuilding the site" true in practice, not just in principle —
see **Adding content** below.

## Changing the brand name / SEO defaults

Everything reads from one file:

```
src/data/site.ts
```

`brandName`, `tagline`, `description`, `contactEmail`, `social`, navigation,
and `defaultSeo` (title template, description, locale) all live there.
`SITE_URL` (used by `astro.config.mjs` for the sitemap/canonical/OG URLs) is
also defined in this same file — one place, not two.

## Adding content later (no code changes)

**New service in an existing category** — add one file, e.g.
`src/content/services/amazon/ppc.md`:

```md
---
title: "Amazon PPC"
slug: "ppc"
category: "amazon"
shortDescription: "One or two sentences for cards and listings."
icon: "trending-up"          # see src/components/ui/Icon.astro for available names
order: 6
whatWeProvide:
  - "Deliverable one"
  - "Deliverable two"
features:
  - "Key feature one"
whoFor: "One sentence on who this service is for."
---

Full introduction copy goes here as markdown — shown at the top of the
service page, above "What we provide".
```

It will automatically appear: on `/services/`, on its category page, in
the header's Services dropdown (desktop and mobile), as a "related
service" on its sibling services' pages, and at its own page
`/services/amazon/ppc/` — nothing else needs to change.

**New category** — add a file under `src/content/categories/`, then point
new services at it via their `category` field. It appears in the header
dropdown, footer, `/services/` overview, and — as of the Home page's
per-category loop — gets its own full showcase section on the Home page
too, automatically, in the same order as the categories collection.

**New FAQ** — add a file under `src/content/faqs/`. Set `featured: true` to
surface it on the Home page preview, and/or `relatedService: "<slug>"` to
surface it on that service's page too.

**New portfolio item** — add a file under `src/content/portfolio/` with
`isPlaceholder: false` once it's a real, verifiable sample, and a
`portfolioCategory` matching one of the entries in
`src/content/portfolio-categories/`. Do not mark fabricated work as real.

**New portfolio category** — add a file under
`src/content/portfolio-categories/`.

## Running locally

Requires Node.js 18.20+ (Node 20/22 also fine).

```bash
npm install
npm run dev       # http://localhost:4321
npm run build     # outputs to dist/
npm run preview   # preview the production build locally
```

## What was verified, and what was not (read this before trusting the build)

This project was written in a cloud sandbox whose network policy blocks
`npm install` from the public npm registry (confirmed by direct testing —
`registry.npmjs.org` and `pypi.org` both return `403 host_not_allowed` at
the proxy level; re-tested most recently on 2026-08-30, one attempt, same
result — this is not transient). **This means the Astro compiler itself
has never run on this code — it has not been built, and it has not been
opened in a browser from within this environment.** Do not treat it as
tested until one of the two steps below happens.

What *was* done, as a substitute for a real compile (most recently
re-verified in full on 2026-08-30, after the Home-page per-category loop
change):

- Every `.astro`, `.ts`, and the `.mjs` config file (33 files) was checked
  for balanced `{}` `()` `[]`. **Zero imbalances found.**
- Every one of the 25 Markdown content files' YAML frontmatter was parsed
  and validated as well-formed. **Zero errors.**
- Every content file's frontmatter fields were checked against its
  collection's Zod schema in `content.config.ts` — required fields present,
  no unexpected fields. **Zero errors.**
- Every cross-reference between collections was checked: each service's
  `category` matches a real category slug, each portfolio item's
  `portfolioCategory`/`serviceCategory` matches a real one, each FAQ's
  `relatedService` matches a real service slug, and no two services in the
  same category share a slug. **Zero errors.**
- Every internal link in every component/page (literal `href="..."` values,
  plus the data-driven nav/footer paths in `site.ts`) was cross-checked
  against the actual static routes and the dynamic route patterns
  `getStaticPaths()` generates. **All resolve.**
- Every icon name referenced from content frontmatter, component code, and
  the Home/About pages' inline arrays was cross-checked against the icon
  set actually defined in `Icon.astro`. **All exist.**
- Both `getStaticPaths()` functions (category pages, service pages) were
  read end-to-end to confirm they derive every route from `getCollection()`
  with no hardcoded slugs — the scalability requirement holds in the code,
  not just in the README's claim.
- Confirmed no CDN script tags or missing build-tool wiring anywhere in
  `src/`/`public/` — Tailwind is loaded exclusively through
  `@tailwindcss/vite` in `astro.config.mjs` and `@import "tailwindcss"` in
  `global.css`, the same as it always has been in this project (this check
  was prompted by an unrelated, separate static HTML preview file having
  briefly shipped without its Tailwind CDN `<script>` tag — that file is
  not part of this Astro project and the bug never existed here).

What this does **not** catch: type mismatches against the real Zod schemas
and Astro's actual types, real component rendering, CSS/Tailwind class
validity as applied by the real compiler, and — most importantly — how it
actually looks and behaves in a browser. **The first real build (via
Cloudflare Pages, or `npm install` on your own machine) is still a genuine,
unperformed test, and its result should be checked before this is
considered launch-ready.**

## Deploying to Cloudflare Pages (free)

1. Push this project to a GitHub repository (private is fine).
2. In the Cloudflare dashboard: **Workers & Pages → Create → Pages → Connect
   to Git**, and select the repository.
3. Build settings:
   - **Framework preset:** Astro
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
4. Deploy. Cloudflare gives you a free `*.pages.dev` URL immediately — this
   is your free test environment. Every push to `main` redeploys it
   automatically, and every other branch/PR gets its own free preview URL.
5. Once it builds successfully, update `SITE_URL` in `src/data/site.ts` to
   the actual `*.pages.dev` URL Cloudflare assigned, commit, and it will
   redeploy with correct sitemap/canonical/OG URLs.
6. **Do not connect a custom domain or buy anything yet.** Work through the
   testing checklist below on the free `*.pages.dev` URL first.

Nothing here requires a credit card, a paid plan, or an account upgrade.

## Testing checklist (do this before trusting the site, and before any domain)

- [ ] `npm run build` completes with no errors — **this is the first real
      test this project has had; do it before anything else below**
- [ ] Every route above loads (no 404s) — click through, don't just scan
- [ ] Every nav link, footer link, and CTA button resolves correctly
- [ ] Header Services dropdown works on desktop (hover) and mobile (tap to expand)
- [ ] Mobile menu opens/closes correctly on a real phone or narrow viewport
- [ ] Resize through mobile / tablet / desktop widths — check for layout breaks
- [ ] Contact form: submit empty (should block via validation), submit valid
      (should show the "not connected yet" message, not fail silently)
- [ ] 404 page appears for a made-up URL and its links work
- [ ] View source / dev tools on a couple of pages — check `<title>`, meta
      description, canonical tag, and JSON-LD are present and correct
- [ ] Run the deployed `*.pages.dev` URL through PageSpeed Insights /
      Lighthouse (performance, accessibility, SEO tabs)
- [ ] Tab through the site with keyboard only — focus should always be visible
- [ ] Check browser console for errors on a few different pages
- [ ] Re-read every page for placeholder text that shouldn't ship as-is
      (contact email in `site.ts`, Privacy/Terms bracketed placeholders)

## Design system

Design tokens (colors, fonts, radius, shadows, container width) are defined
once in `src/styles/global.css` under the Tailwind v4 `@theme` block —
components use the resulting utility classes (`bg-brand-700`, `rounded-lg`,
`shadow-soft`, `max-w-page`, etc.) rather than one-off arbitrary values, so
the whole site stays visually consistent as pages are added.
